Lesson 3.1 — What Are AI Agents?
Agents are AI systems that perceive their environment, make decisions, and take multi-step actions without a human prompt at each step. For product and engineering, this means: an agent that reads your backlog, researches user feedback, drafts a spec, and routes it for review — all automatically. Key concepts: tool use, memory, planning, multi-agent collaboration, and the ReAct loop (Reason → Act → Observe → Repeat).

Lesson 3.2 — Agentic RAG (AI + Your Data)
Retrieval-Augmented Generation 2.0: instead of just searching once and summarizing, Agentic RAG actively searches, evaluates whether it found enough, and searches again if needed. For product work: imagine an agent that reads your Jira tickets, user research docs, and analytics data to automatically surface the right context for a decision.

🤖 A.G.E.N.T. Framework Worksheet
This is your core Module 3 deliverable — an implementation-ready brief for an agentic workflow. The same output the Harvard HDSR course produces at the end of 2.5 weeks.
Step 0 — Choose a workflow to design
Quick-pick a common Product/Engineering workflow:
A
Assess & Audit the Workflow
Map it. Score it. Decide if it's agent-ready.
Map the workflow in detail: what triggers it, what data it touches, who does each step, and how long each step takes. An agent-ready workflow is high-volume, rule-based at key steps, language-heavy, and doesn't require nuanced human judgment at every decision point.
Current workflow steps (write them out, step by step)
Inputs (what data / triggers does this workflow use?)
Current time cost & frequency
Agent-readiness score: which steps are most repetitive / rule-based?
G
Goal & Outcome Definition
What does success look like, exactly?
Vague goals produce vague agents. Define the outcome you want with enough precision that you could evaluate whether the agent achieved it. Also define where humans stay in the loop — the Harvard course stresses this: agents take actions, humans make final decisions on high-stakes steps.
Primary goal (what should the agent produce or achieve?)
Success criteria (how will you know it worked?)
Human-in-the-loop checkpoints (what must a human review before action?)
What is out of scope / what should the agent NOT do?
E
Experiment with a Pilot
Run a real test. Gather evidence. Don't over-engineer.
The Harvard course emphasizes: pilot first, scale second. Design the smallest possible experiment that tests whether an agent can handle the core steps. For most product/engineering workflows, this means starting with Claude Projects or a simple n8n automation, not custom code.
Pilot design — what is the simplest version of this agent you could test this week?
Tools to use for the pilot (no-code/low-code preferred)
How will you evaluate the pilot output? What metrics?
Pilot results (fill in after running it)
N
Navigate Governance & Risk
Gartner: 40% of agentic AI projects fail due to poor governance — not bad technology.
Before scaling, identify the risks. For product and engineering workflows, common risks include: data privacy (don't send customer PII to public AI APIs), accuracy requirements (is a 10% error rate acceptable?), and access control (which systems can the agent read/write?).
Data & privacy concerns
Accuracy requirements (what's the acceptable error rate?)
Access controls (what can the agent read/write/trigger?)
Compliance / policy constraints
T
Transform & Scale
3+ use cases in production = 160% ROI. Plan your portfolio.
Once the pilot proves value, design the scaled version and identify your next 2 use cases to run in parallel. Research shows 3+ concurrent AI use cases achieve 4× the ROI of a single use case.
Scaled version — what would production look like? (tools, triggers, integrations)
Next 2 use cases for your AI portfolio (to reach 3+ total)
90-day milestones
Expected time savings per week (once scaled)
